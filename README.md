# 泛微 E9 WEF 双向布局转换工具

## 在线使用

静态网页由 GitHub Pages 托管。选中的 `.wef` 由浏览器本地解码、转换和下载，网页不设文件上传接口。

## 本地开发

需要 Node.js 18+。在本目录运行：

```bash
npm install
npm run build
npm run preview
```

浏览器打开 `http://127.0.0.1:8765`。`dist/` 是可直接部署到静态托管平台的目录。

## 使用

1. 点击上传区，在同一个文件选择窗口中同时选中一份流程节点布局 `.wef` 和一份建模表单布局 `.wef`。顺序不限，也接受此前解出的 JSON。
2. 两份文件选齐后自动分析。界面根据 `wfid`/`nodeid` 或 `modeid` 判断类型；更换文件后也会重新分析。
3. 选择“流程布局 → 建模”或“建模布局 → 流程”，检查布局预览和字段匹配清单。
4. 如果来源布局有目标表单未匹配字段，核对清单后勾选省略确认。
5. 点击“生成候选 WEF”，下载 `.wef` 或 JSON，先在 E9 设计器中测试导入。

转换沿用**来源布局的排版**，并保留**目标表单的标识与字段 ID**。字段按名称和控件类型匹配。目标表单中不在来源布局出现的字段不会显示在候选布局里；不会修改底层字段。反向转换时，来源中未匹配的字段会从候选布局省略，界面会要求明确勾选。

本工具完成本地加密、解密及 JSON 回读验证。跨流程/建模类型的导入行为尚未在 E9 设计器验证；导入前请备份目标布局，并检查字段控件、权限、联动、公式和明细表。

## 本次示例验证

使用 `技术（研发）人员信息维护_技术人员.wef` 与 `（2026）技术人员信息（new）新建模板.wef` 双向测试：流程到建模匹配 49 个字段，保留建模 `formid=-3491`；建模到流程匹配 49 个字段、省略 15 个未匹配来源字段，保留流程 `formid=-810`。两种上传顺序与两种方向均通过本地生成和解密回读。
